- **New meetings don't reach the live database automatically (surfaced by Task 10).** The "Scrape" pipeline stage (design spec §5.1) was never rewritten to write `meetings`/`bodies` rows to the database directly — `scripts/run_scrapers.py` still only writes to `data/meetings.json`, which nothing live reads anymore. The only path from that JSON into the database is `db/migrate.py`, a destructive full rebuild that would wipe every document/tag/briefing produced since. Until this is fixed (rewriting the scrape stage to upsert into `meetings`/`bodies` directly, on `external_id`, the same idempotency key the design already calls for), new meetings need to be added to the live database by hand. `POST /api/admin/refresh` (Task 10) only covers capture/extract/tag/brief, which are safe to re-run.
